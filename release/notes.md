账号探测 v0.1.13

- 修复测票间隔较短（如 10 分钟）的账号用了一段时间后，立即探测报“请求失败（HTTP 502）”、自动探测也不再记录的问题：账号的探测历史超过了 CPR 单条插件状态 256 KiB 的上限，之后每次写入都被拒绝
- 历史超过 240 KiB 时，先从最旧的开始去掉已无详情的摘要的判定理由，还不够就丢最旧的摘要；状态条、正常率和当前判定不受影响，只是间隔短时保留的天数少于 30 天
- 时间条弹层里去掉理由的记录只显示判定，不再误显示“没有可用的判定”

可从 v0.1.12 更新，不需要改设置；已经写满的账号在下一次探测时自动裁剪恢复。

## v0.1.12

- ModelTrace 改用插件设置里配置的 Client Key（新设置 `modeltraceClientKeyId`，填 CPR Client Key 列表里的 ID，不是 Key 本身）；不填则 ModelTrace 被拦截，测票不受影响
- 插件不再自建 Client Key“账号探测（ModelTrace）”和分组“账号探测”，也不再每轮把账号加进这个分组；已经建好的这两个请在 CPR 里手动删除（插件 SDK 删不掉）
- 配置的 Key 要能访问所有要测的账号（建议不绑分组）；探测用量计入这个 Key，也受它的限额约束

可从 v0.1.11 更新。更新后先在插件设置里填好 ModelTrace 使用的 Client Key ID，再删除旧的“账号探测”Key 和分组。

## v0.1.11

- 自动分组改为**只在测票当前判定变化时调整，只动判定变了的那个账号**：新判定符合、旧判定不符合的分组加入，旧判定符合、新判定不符合的分组移出，其他分组不动
- 去掉每 5 分钟的全量核对：不再纠正 CPR 里的手动改动；保存设置、删除规则、关闭自动分组都不改成员（删除插件新建分组的规则不再清空成员）
- 开启自动分组时以各账号当前判定为起点，不补之前的变化；插件重启后补上重启前已确认、还没来得及调整的变化
- 调整失败下一轮重试；重名、分组被删这类配置问题不重试。页面显示最近 20 次调整（账号、判定变化、加入和移出的分组）

保持插件 ID 不变，可从 v0.1.10 更新。更新后各账号以当前判定为起点，现有分组成员不变。

## v0.1.9

- 新增设置 `cprAdminUrl`（CPR 地址）与敏感配置 `cprAdminApiKey`（CPR 管理 API Key）；只在选了现有分组时使用，插件只读分组、读账号所在分组、改账号的分组（`accounts/batch-update` 只带 `accountIds` 和 `groupIds`），Key 不进历史、页面响应或错误信息

- 注意：管理 API Key 拥有 CPR 全部管理权限；CPR 的分组是整体替换，读写之间的手动改动会被覆盖；管理员接口不是插件的稳定合同，CPR 升级后可能需要适配

保持插件 ID 与状态结构不变，可从 v0.1.8 更新，原设置、自动分组规则和历史保留。

## v0.1.8

- 新增自动分组：按测票当前判定（连续 3 次确认）自动调整 CPR 分组成员，Client Key 绑定“测票正常”这类分组即可只调度正常账号
- 分组可配置（最多 8 个）：分组名、颜色、放进来的判定（正常 / 疑似 / 降智 / 未判定，可多选）；首次打开给出“测票正常”“测票异常”两条建议规则，保存后生效
- 插件只管理自己建的分组，名称和颜色只在创建时使用，之后在 CPR 分组管理里修改；与已有分组重名时在规则下提示
- 刚测完的账号下一轮维护调整，每 5 分钟全量核对并纠正手动改动；不支持探测的账号不进任何组；关闭后成员保持不变，删除规则会先清空成员
- 自动分组只改分组成员，不发探测、不读凭据，默认关闭

保持插件 ID 与状态结构不变，可从 v0.1.7 更新，原设置和历史保留。

## v0.1.3
