账号探测 v0.1.3

- 新增 TG 机器人通知配置：独立敏感字段 Bot Token、Chat ID、可选话题 ID，以及首页测试通知按钮
- 新增持久化的当前测票判定：连续 3 次正常恢复，连续 3 次疑似/降智确认异常；异常的 3 次中出现降智则判降智，否则判疑似
- 手动与自动测票一起计数；失败、未判定或切换模型中断计数；重启不丢失进度。状态改变才通知，首次确认正常不通知
- 当前判定不再由时间范围内最严重的历史结果决定；单次结果、时间条和正常率不改写，ModelTrace 不参与连续测票计数
- TG 通知队列持久保存，失败后台退避重试、遵守限流，详情展示待发数量和脱敏错误；关闭通知不影响判定更新

**配置说明：** 在 CPR 插件详情设置 TG 通知开关和 Chat ID，在敏感配置填写 `telegramBotToken`。先用首页的测试通知验证。服务器须能访问 `api.telegram.org`。升级保持插件 ID `milesians.cpr-turnstate` 不变，原设置与历史保留；以最近一次有效测票结果作为初始判定，不补发历史通知。

要求 Codex Proxy RS `>=3.34.0, <4.0.0`，默认关闭真实探测和 TG 通知。

## v0.1.2

- 插件 ID 改为 `milesians.cpr-turnstate`，发布者改为 `milesians`
- 默认模型：ModelTrace `gpt-6.1-sol`，测票 `gpt-6-luna`；已有账号选择继续保留，空模型使用对应方法的默认值
- 每个账号可独立配置自动探测开关、模型和间隔；立即探测弹窗切换方法时分别保留模型选择
- 列表新增勾选、按当前筛选全选和批量配置（每批最多 200 个账号），可统一修改模型、开关、间隔，也可保持部分项目原值；整批校验后一次保存，保存不触发立即探测

**安装说明：** CPR 把新 ID 视为独立插件，不能直接从旧 `ezou.account-probe` 实例切换版本。请先停用旧实例，再从 GitHub 来源 `Milesians/cpr-turnstate` 安装 v0.1.2；旧设置和历史仍保留在旧实例，不会自动迁移。

要求 Codex Proxy RS `>=3.34.0, <4.0.0`，默认关闭真实探测。
